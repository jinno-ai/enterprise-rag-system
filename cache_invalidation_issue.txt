## 概要
現状のキャッシュ実装（Issue #34）を強化し、データの更新や有効期限に基づいたインテリジェントなキャッシュ無効化機構を実装します。これにより、ドキュメントの更新時に古い情報が返されるのを防ぎ、システム全体の整合性とパフォーマンスを維持します。

これは実装ロードマップの Phase 3.2 (Caching Strategy) に該当するタスクです。

## 実装内容
1. **TTL (Time-To-Live) ベースの失効**:
   - 各キャッシュエントリに有効期限を設定し、Redis 等の機能を活用して自動的に削除・更新する仕組み。
2. **イベント駆動型の無効化**:
   - ドキュメントの新規登録、更新、削除に連動して、関連する検索結果やLLM応答のキャッシュを即座に無効化（Eviction）する。
3. **予測的プリウォーミング (Predictive Pre-warming)**:
   - 頻繁にアクセスされるクエリや、新しく追加された重要ドキュメントに対して、バックグラウンドで事前にキャッシュを生成する仕組み。

## 実装タスク
- [ ] Redis を活用したキャッシュ管理クラスの拡張と無効化ロジックの実装
- [ ] ドキュメント管理 API とキャッシュ無効化イベントの統合
- [ ] 設定ファイルでの TTL および詳細なキャッシュポリシー（L1/L2 等）の定義
- [ ] キャッシュ整合性を担保するためのユニットテストの追加

## 期待される効果
- データ更新後の即時反映による検索結果の正確性（整合性）の向上。
- 不要な LLM API 呼び出しのさらなる削減によるコスト最適化。
- 大規模環境におけるレスポンス速度の安定化。
