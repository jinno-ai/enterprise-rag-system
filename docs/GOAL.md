## goal（本質的ゴール）

散在する企業内ナレッジ（PDF / Markdown / Docx / HTML / Confluence / Notion 等）に対し、
**意味検索とLLMを組み合わせ、正確・低レイテンシ・本番運用可能な質問応答を提供する
RAG プラットフォーム**を完成・運用すること。

単なる検索ツールではなく、以下を満たす「プロダクション品質」を目指す:
- 高い回答精度（ハルシネーション抑制 / 出典提示）
- 本番運用に耐える可観測性・セキュリティ・スケーラビリティ
- 継続的に精度とコストを改善できる評価基盤

## constraints（制約条件）

- **技術スタック**: Python 3.10+ / FastAPI / Celery / Redis / PostgreSQL（既存構成を踏襲）。
  ベクトルDBは Pinecone(主) / Weaviate(代替) / FAISS(ローカル) を想定。
- **既存資産の尊重**: `app/` 配下の既存モジュール構造・命名・スタイルに揃える。
- **設定の外部化**: シークレット・接続情報・パスはハードコードせず環境変数 / `config.py` 経由
  （`.env.example` を更新）。
- **後方互換**: 既存 API の互換性を破壊する変更は破壊的変更として人間にエスカレーションする。
- **セキュリティ**: 既存のセキュリティミドルウェア（XSS/SQLi/パストラバーサル検査、
  レート制限、PII 検出、セキュリティヘッダ）を退行させない。
- **OS/環境**: 開発は Windows + bash 互換シェル。クロスプラットフォームで動くコードを書く。

## assumptions（前提 / 仮説と確信度）

> 不足情報は質問せず仮説で補完する（Autonomous Development Workflow Principle 3）。
> 確信度が 70% 未満になった項目のみ人間に確認する。

- 社内（エンタープライズ）利用を前提とする。〔確信度 95%〕
- LLM プロバイダは Anthropic Claude を第一候補、OpenAI 互換も許容。〔確信度 70%〕
  - ※ コードは OpenAI クライアント前提の箇所があるため、実装時に現状を確認して整合させる。
- 開発の進め方は**エピック駆動**（`EPIC_PLANNING.md` の E-01〜E-04）に従う。〔確信度 90%〕
- 優先順位は E-01 技術基盤の適正化 → E-02 RAG精度 → E-03 エンタープライズ → E-04 スケール。
  〔確信度 90%〕

## roadmap（実行順）

詳細は `PROJECT_SCHEDULE.md` / `EPIC_PLANNING.md` を参照。要約:

1. **E-01 / Week 0 — 技術基盤の適正化（最優先・25h）**
   テスト基盤＋CI、セキュリティ/構成管理（CORS・ハードコード排除）、AsyncIO 最適化、
   構造化ロギング、DI リファクタリング（`ISSUES.md` の Issue 1〜5）。
2. **E-02 / Phase 1 — 検索・RAG精度の高度化（160h）**
   高度なドキュメント処理、Dense/Sparse/Hybrid 検索、Re-ranking + RRF、HyDE / Query
   Decomposition / CoT・ReAct。
3. **E-03 / Phase 2 — エンタープライズ機能（90h）**
   OAuth/RBAC、マルチテナンシー、PII・監査ログ。
4. **E-04 / Phase 3 — スケーラビリティ（70h）**
   非同期タスクキュー、キャッシュ戦略、ベクトル検索最適化。

## working_agreement（自律開発の運用契約）

`autonomous-development-workflow` スキルに準拠して進める。

- **意思決定ポリシー**: 確信度 ≥90% は自動実行 / 70–89% は提案後に実行 / <70% は人間確認。
- **実装単位**: 小さく検証可能な単位で進め、1 変更ごとにテスト・lint が通る状態を保つ。
- **ドキュメント**: 実装と同時に更新（README / ADR / API 仕様 / 変更履歴）。後追いで書かない。
- **人間へのエスカレーション**: 事業戦略・重大脆弱性・法的問題・予算超過・確信度<70%・
  破壊的変更（API 非互換、`main` への push、本番デプロイ、データ削除等）のみ。
- **完了は存在しない**: すべての成果物は継続改善の対象（Continuous Improvement Loop）。
